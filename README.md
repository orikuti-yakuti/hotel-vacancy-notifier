# ホテル空室通知（LINE）

指定したエリア（駅の周辺）で、条件に合うホテルの空室を30分ごとにチェックし、**新しく空室が出たらLINEに通知**する仕組みです。
GitHub Actions（無料）で動くので、パソコンやスマホを閉じていても動き続けます。

```
GitHub Actions（30分ごと）
   └─ 楽天トラベル空室検索API で、指定した駅の周辺・日付・条件の空室を確認
        └─ 条件に合う空室が新しく出たホテルを LINE にプッシュ通知
```

- 駅名で範囲を指定（例：蒲田・川崎・鶴見・横浜の各駅から1km以内）
- 料金の範囲、禁煙/喫煙、シングル/ダブルなどの部屋タイプで絞り込み
- カプセルホテル・相部屋を除外、指定したホテルも除外できます
- 同じホテルで何度も通知しません
- 通知が来ても**予約は自動では取れません**。リンクを開いて自分で予約してください

> 画面の操作をもっと詳しく知りたい場合は、Word版の「セットアップ手順書（詳細版）」を見てください。

### 使っているデータ

- 空室・料金：[楽天トラベル](https://travel.rakuten.co.jp/) の空室検索API（公式）
- 駅の位置：[HeartRails Express](https://express.heartrails.com/)（無料の駅データAPI）

楽天トラベルに掲載されていないホテルや、楽天に割り当てられていない在庫は対象外です。

## セットアップ（初回だけ・40〜60分）

用意するもの：GitHub アカウント、楽天会員アカウント、LINE アカウント、パソコン

### 1. GitHub にリポジトリを作る

1. GitHub で **New repository** → 名前は `hotel-vacancy-notifier` など（作成済みならそのままでOK）、**Private（非公開）** を選んで作成
   - 監視条件（泊まるホテル・日付）が書かれるので、非公開にしてください
   - 30分ごとのチェックなら、非公開リポジトリの無料枠（月2,000分）に収まります
2. 作成直後の画面の「**uploading an existing file**」（または **Add file → Upload files**）から、
   `check_vacancy.py`、`find_hotel.py`、`watches.toml`、`README.md` をアップロードして **Commit changes**

> ⚠️ `.github` フォルダはアップロードしないでください。ブラウザからは正しく取り込まれません。手順2で画面上から作ります。

### 2. ワークフローファイルを画面上で作る

1. **Add file → Create new file**
2. ファイル名に `.github/workflows/check.yml` と入力（`/` を打つとフォルダになります）
3. このフォルダの `.github/workflows/check.yml` の中身を貼り付けて **Commit changes**
4. 同じ方法で `.github/workflows/find-hotel.yml` も作る
5. **Actions** タブに「空室チェック」と「ホテル番号を調べる」が並べば成功

> 「a file exists where you're trying to create a subdirectory」と出たら、`.github` または `workflows` という名前の**ファイル**（紙のアイコン）ができています。それを開いて「…」→ **Delete file** で削除してから、やり直してください。

### 3. 楽天ウェブサービスでアプリIDを取る

1. [楽天ウェブサービス](https://webservice.rakuten.co.jp/) に楽天IDでログイン
2. 「+アプリID発行」から登録

   | 項目 | 入力例 |
   |---|---|
   | アプリ名 | ホテル空室通知 |
   | アプリURL | リポジトリのURL（`https://github.com/ユーザー名/リポジトリ名`） |
   | 許可されたWebサイト | `github.com`（**ドメイン名だけ**。`https://` などは付けない） |
   | 利用目的 | 個人利用（ホテルの空室確認） |
   | 想定QPS | 1 |

3. 発行された **アプリID** と **アクセスキー** をメモ

> 「無効なドメイン」と出たら、全角文字や前後の空白・改行が入っていないか確認してください。手で打たずにコピー＆貼り付けすると確実です。だめなら `*.github.com` を試します。

### 4. LINE公式アカウントを作り、Messaging API を有効にする

LINE Notify は2025年3月に終了したため、LINE公式アカウント（無料プラン）の Messaging API を使います。

> ⚠️ LINE Developers の「新規チャネル作成」は使いません。Messaging API チャネルは、**LINE Official Account Manager で有効にすると自動で作られます**。この操作は**パソコンのブラウザでしかできません**。

1. [LINE Official Account Manager](https://manager.line.biz/) にログインし、公式アカウントを作成
   （ビジネスマネージャーとの接続を求められたら、案内に従って接続）
2. アカウント一覧から、作った公式アカウントを**クリックして中に入る**
3. 右上の **設定** → 左メニューの **Messaging API**
4. ステータスが「未利用」であることを確認し、**Messaging APIを利用する** を押す
5. プロバイダーを選択（または新規作成）→ 確認画面でアカウント名とプロバイダー名を確認して **OK**
6. ステータスが「**利用中**」になれば完了

### 5. LINEのユーザーIDとトークンを取得する

1. [LINE Developers コンソール](https://developers.line.biz/console/) に同じLINEアカウントでログイン
2. 手順4で選んだプロバイダー → **チャネル設定** タブ → **Messaging API** と書かれたカードを開く
   （「LINEミニアプリ」のカードは別物です）
3. **チャネル基本設定** タブの一番下 → **あなたのユーザーID**（`U…`）をメモ
4. **Messaging API設定** タブの一番下 → **チャネルアクセストークン（長期）** を「発行」してメモ
5. 同じタブのQRコードを LINE で読み取り、**公式アカウントを友だち追加**（しないと通知が届きません）

### 6. GitHub に秘密情報（Secrets）を登録する

リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で、次の4つを登録します。

| Name | 値 |
|---|---|
| `RAKUTEN_APP_ID` | 楽天のアプリID |
| `RAKUTEN_ACCESS_KEY` | 楽天のアクセスキー |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINEのチャネルアクセストークン（長期） |
| `LINE_USER_ID` | LINEの「あなたのユーザーID」（`U…`） |

### 7. LINE に届くかテストする

**Actions** → **空室チェック** → **Run workflow** → 実行モードで **LINEテスト通知** を選んで実行。
1分ほどで LINE に「✅ ホテル空室通知のテストです」が届けばOKです。

### 8. 監視条件を書く

リポジトリの `watches.toml` を開き、鉛筆アイコンで編集します。

```toml
[[watch]]
name = "蒲田〜横浜"
checkin = "2026-12-20"
checkout = "2026-12-21"
adults = 1
rooms = 1

stations = ["蒲田", "川崎", "鶴見/神奈川県", "横浜"]   # エリア（駅名・複数可）
radius_km = 1.0                                       # 各駅から何km以内か（0.1〜3.0）

min_price = 4000          # 1部屋・1泊あたりの下限（税込）
max_price = 9000          # 1部屋・1泊あたりの上限（税込）

smoking = "禁煙"          # "禁煙" / "喫煙" / "どちらでも"
room_types = ["シングル", "ダブル"]   # "シングル" "セミダブル" "ダブル" "ツイン" "トリプル"

exclude_capsule = true                      # カプセル・ドミトリー・相部屋などを除く
exclude_hotels = ["○○イン", 123456]          # 通知してほしくないホテル（名前の一部か施設番号）
```

編集したら **Commit changes**。次回のチェックから反映されます。

| 項目 | 説明 |
|---|---|
| `stations` | 駅名のリスト。「駅」は付けても付けなくてもOK。同じ名前の駅が複数の都道府県にある場合は `"鶴見/神奈川県"` のように `/都道府県` を付けます |
| `radius_km` | 各駅からの距離（km）。0.1〜3.0。駅前だけなら `0.5`、広めに探すなら `2.0` など |
| `min_price` / `max_price` | 1部屋・1泊あたりの料金（税込）の範囲。片方だけでも、両方省略しても構いません |
| `smoking` | `"禁煙"` / `"喫煙"` / `"どちらでも"`。部屋名・プラン名の「禁煙」「喫煙」で判定します |
| `room_types` | 部屋名・プラン名で判定します。`[]` にすると問いません。`"ダブル"` に `"セミダブル"` は含まれません |
| `exclude_capsule` | `true` でカプセルホテル・ドミトリー・相部屋・ゲストハウス・ホステルなどを除きます |
| `exclude_hotels` | 名前の一部（`"○○イン"`）か楽天の施設番号（`123456`）。複数書けます |
| `exclude_keywords` | ホテル名・説明にこの言葉を含むものを除きます（任意） |
| `hotels` | 駅ではなく、特定のホテルを楽天の施設番号で指定する場合（15件まで） |
| `enabled` | `false` にすると一時停止 |

> ⚠️ 楽天には「鍵付きかどうか」の項目がないため、`exclude_capsule` は宿名・説明・部屋名に含まれる言葉（カプセル、ドミトリー、相部屋など）で判定しています。すり抜けたホテルがあれば `exclude_hotels` に追加してください。

### 9. 動作確認して、除外したいホテルを決める

1. **Actions → 空室チェック → Run workflow** を **通知せずに確認** で実行
2. 実行を開き、**check** → **空室を確認** を開くと、条件に合うホテルの一覧と、除外したホテルが表示されます

   ```
   ✅ 蒲田〜横浜 2026-12-20〜2026-12-21: 条件に合う空室 3件（新しく空いた 3件）
          7  ホテルE川崎  シングル 5,500円 / 川崎駅から約0.1km
          1  ホテルA蒲田  禁煙シングル 6,200円 / 蒲田駅から約0.1km
      除外したホテル:
          2  カプセルイン蒲田（カプセル・相部屋タイプ）
   ```

3. 通知してほしくないホテルがあれば、左端の番号か名前を `exclude_hotels` に追加します

あとは30分ごとに自動で動きます。

### 通知のルール

- 条件に合う空室が**新しく出たホテル**だけを通知します。同じホテルで何度も通知しません
- 一度空室がなくなってから再び空いたら、また通知します
- 1回の通知にまとめて最大10件（安い順）を載せます
- 監視を始めた直後は、その時点で空いているホテルがまとめて通知されます
- `watches.toml` の条件を変えると、別の監視として扱われ、最初からやり直します

### 補足：ホテルの番号を調べる

`exclude_hotels` や `hotels` に楽天の施設番号を書きたいときに使います（名前で書いても構いません）。

- **Actions** → **ホテル番号を調べる** → **Run workflow** でホテル名を入力して実行。結果の左端の数字が施設番号です
- または、[楽天トラベル](https://travel.rakuten.co.jp/) でホテルのページを開き、URL（`travel.rakuten.co.jp/HOTEL/123456/`）の数字を見ます
- 動作確認（手順9）の一覧の左端の数字も施設番号です

## よくある質問

**Q. チェック間隔を変えたい**
`.github/workflows/check.yml` の `cron: "*/30 * * * *"` を変更します。
非公開リポジトリの無料枠は月2,000分で、1回の実行が1分として数えられます。
30分ごと（月約1,490分）なら枠内ですが、20分ごと（約2,230分）や15分ごと（約2,980分）にすると超えます。
GitHub側の混雑で、実行が数分〜十数分遅れることがあります。

**Q. 監視を止めたい**
`watches.toml` で `enabled = false` にするか、Actions → 空室チェック → 右上「…」→ **Disable workflow**。
チェックイン日を過ぎた監視は自動でスキップされます。

**Q. 実行が失敗した（赤い×）**
失敗した実行を開くと、日本語で原因が表示されます。
- `設定エラー: 環境変数 … が設定されていません` → 手順6の Secrets 名のスペル違い
- `駅「…」が見つかりませんでした` / `複数の都道府県にあります` → `stations` の駅名を確認（`"鶴見/神奈川県"` のように都道府県を付ける）
- `watches.toml の書き方に誤りがあります` → 引用符が全角になっていないか、`[ ]` や `"` の閉じ忘れがないか確認
- `楽天APIがリクエストを拒否しました（403 …）` → 楽天アプリの「許可されたWebサイト」を確認
- `LINEへの送信に失敗しました（400/401）` → トークンやユーザーIDの貼り間違い、または公式アカウントを友だち追加していない

**Q. 空きがあるのに通知が来ない**
一度通知したホテルは、空室がなくなるまで再通知しません。
また、1つの駅につき安い順に最大150プランまで確認します。範囲が広く料金上限がない場合は、高いホテルが対象外になることがあるので、`max_price` を設定するか `radius_km` を小さくしてください。
部屋名に「禁煙」「シングル」などが書かれていないプランは、`smoking` や `room_types` の条件で外れることがあります。

**Q. 通知が多すぎる**
`radius_km` を小さくする、`max_price` を下げる、`exclude_hotels` で除外する、のいずれかで絞ってください。
LINEの無料プランは月200通までです（1回の通知で最大10件をまとめて送るので、1通と数えます）。
